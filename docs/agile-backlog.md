# Agile Product Backlog

## Product goal
Deliver a secure, responsive Jira-style Agile workspace demonstrating production-oriented Angular + .NET 8 engineering practices.

## Epic 1 — Identity & Security
- US-101 As a user, I can sign in securely.
- US-102 As a project member, my project permissions are enforced.
- US-103 As an administrator, I can manage project membership.

## Epic 2 — Issue Management
- US-201 As a member, I can create an issue.
- US-202 As a member, I can update issue details.
- US-203 As a user, I can view issue history/comments.
- US-204 As a user, I can transition an issue through workflow states.

## Epic 3 — Agile Planning
- US-301 As a planner, I can view and filter the backlog.
- US-302 As a member, I can assign an issue to a sprint.
- US-303 As a manager, I can create/start/complete a sprint.
- US-304 As a team, we can view sprint burndown.

## Epic 4 — Reporting
- US-401 As a project member, I can view delivery KPIs.
- US-402 As a project member, I can view completed sprint velocity.
- US-403 As a project member, I can inspect work distribution.

## Definition of Ready
Story has a clear persona, business value, acceptance criteria, dependencies, and test approach.

## Definition of Done
Code implemented; authorization verified; relevant unit/integration/UI tests added; responsive UI reviewed; documentation updated; CI build/test passes.

## Agile workflow
Backlog -> Ready -> In Progress -> Code Review -> Test -> Done.

## Sprint discipline
Sprint scope is explicit. Changes to committed scope are visible through persisted issue/sprint membership. Metrics are calculated from persisted state rather than manually entered values.
